# QA report, 2026-10-09

Scope: exploratory QA of `origin/main` at `20936e2` (merge of PR 95), run on a Mac against the repo's own
fixtures only. No Pi, router or outside network was touched (the QA fixture refuses any non-loopback
connection and records the attempt; none was made). Only new test files and this report were added. Nothing
under `src/` changed.

All numbers below come from commands run in `qa/exploratory-2026-10-09`. Hosted CI is billing-blocked, so
nothing here claims a hosted CI pass.

## Findings

All of these need the admin token, so none is a security hole. Each one answers 500 and writes a traceback to
the journal where it should answer 400 with a sentence a person can read. Every finding has a test marked
`xfail(strict=True)` in `tests/qa/test_api_known_defects.py` (or `test_release_scripts.py`,
`test_settings_transfer.py`). When a fix lands, the strict marker fails the test run and tells whoever fixes it
to remove the marker.

Not defects, but worth knowing:

- The existing browser fixture is not hermetic for update actions. `POST /api/updates/check-online` (and
  install, rollback, retry) reach `updates.py`, which uses `/var/lib/jittersim-updates`, `/opt/jittersim` and
  `systemctl`. On a Mac as a normal user this fails with `PermissionError`; run as root, for example in a
  container, it would write there. The QA fixture (`tests/qa/dashboard_support.py`) stubs every `update-*`
  helper action.
- Profile, device and other names accept control characters, NUL and bidirectional overrides on import and
  through the API (`name: "a\nb"` is saved). They are labels and never reach an nft or tc command (tested), so
  this is a log and display hygiene question only.
- A client that sends a body over the size limit while the server answers 400 and closes may see a connection
  reset before it reads the answer (Python's `http.client` raises `BrokenPipeError` on a 1.1 MB import). A raw
  socket reads the 400 correctly.

## What was tested and what held

1. API robustness (`tests/qa/test_api_robustness.py`, `api_support.py`, `dashboard_support.py`)
   - 88 POST routes and 59 GET routes of a local fixture dashboard (real server, repository and helper over a
     unix socket, fake executor).
   - Property-based: 300 examples of random JSON objects and 300 of random bytes per run, with keys taken from
     the field names in the server source and values from boundary, unicode, huge and type-confused sets.
   - Single-key mutation: 89,760 requests (every route, 85 field names, 12 hostile values) in 85 seconds. This
     is how findings 2 to 4 were enumerated.
   - 23 query strings on every GET route, 18 raw protocol cases (bad lengths, chunked, duplicate headers, TLS
     bytes on a plain port, huge header or URL, traversal, double slash), stalled sockets, a half-sent body
     (dropped after 10 seconds), 20 idle connections against the health check.
   - Held: no hang, no traceback in any body, no token in any response or log line, every `/api` answer JSON
     (except finding 6), 401 for every missing, wrong, truncated, padded or non-Bearer token on every route and
     the double slash path gives no bypass. The server answered the health check after every run.
   - `schemathesis` was not used: the server exposes no OpenAPI spec. Requests were generated from the routes in
     `WRITE_PATHS` and the `response_for` code instead.
2. Settings import and export (`tests/qa/test_settings_transfer.py`)
   - Held: export, import, export is identical (three cycles) with profiles, devices, groups, schedules,
     scenarios, limits, service lists and assignments, policies, protected devices; versions 1 and 2 files are
     read and keep the sections they do not carry; a refused import changes nothing; every limit is enforced
     at the edge (delay, jitter, loss, bandwidth, burst, seed, intervals, name and id lengths, unicode and
     boolean-as-number types); duplicates are refused by name; 16 devices are refused cleanly; wrong shapes of
     every section give 400; the export holds no token or password; a body over 1 MiB is refused in JSON.
   - Property: any single hostile value placed anywhere in the exported document is either refused with 400 or
     gives settings that re-import, round trip and apply (400 examples). Finding 7 is the only flaw.
3. Compiler and plan (`tests/qa/test_compiler_properties.py`, 120 examples each, plus mutation checks)
   - Held: the same input gives the same plan and commands in any order; the command count and nft script size
     are bounded; no name, however hostile, reaches an argument, comment or the nft script; every tc argument
     is made of `[A-Za-z0-9:._%/+-]`; a stateful kernel model shows that after any sequence of one to three
     applies a reset leaves no project table, queue or filter and does not touch foreign tables or queues.
     Two deliberate mutants (reset forgets a table, the nft script gains an injected comment) are caught.
4. Browser (`tests/qa/browser_explorer.py`, `tests/qa/test_browser_explore.py`)
   - The explorer pressed every visible control on every page at 1440 and 375 pixels (about 300 controls per
     width). Detectors were checked against a deliberately broken page first.
   - Held: no uncaught exception, no layout overflow (page or element), no stuck Loading text, no `undefined`,
     `NaN` or `[object Object]` on screen, Tab moves through the page everywhere, no focus trap, one unlabeled
     control (a visually hidden username field for password managers).
   - The console errors seen are the browser logging the HTTP errors that the fixture answers on purpose: 409
     (device save conflict), 400 (site rule with no domains) and 503 (online settings, helper stub). The page
     also probes the Pi's `.local` name for its one-address link; a machine that cannot resolve it logs
     `ERR_NAME_NOT_RESOLVED` (expected).
   - One explorer result was an artefact and is not a defect: Escape seemed not to close three confirmation
     dialogs because a pinned help tip took the first Escape. In isolation Escape closes the dialog at once.
   - The quick pass (no clicking) is a test and runs in about one minute. The full pass is a script:
     `python -m tests.qa.browser_explorer qa-browser-report`.
5. Clean install
   - `python -m build --wheel` gives `jittersim-0.2.0-py3-none-any.whl` with all 11 packaged dashboard assets
     (html, css, js) and the 8 console scripts. A fresh venv outside the repo installs it with its dependencies.
     `jittersim` and `jittersim-dashboard`, `-helper`, `-browser-proxy`, `-service-watch`, `-adblocking`,
     `-reset`, `-access-restore` and 26 documented `jittersim` subcommands all answer `--help` with exit 0.
   - The installed `jittersim-dashboard` starts in configuration-only mode, serves a 732 KB page with no
     unreplaced marker and no external asset, answers the public and token routes, saves a profile, and refuses
     an apply with a plain 503 because no helper is there.
   - `pip-audit` on the installed dependencies (certifi, charset-normalizer, idna, pycryptodome, requests,
     urllib3): no known vulnerabilities.
   - `bandit -r src -ll`: 2 high, 20 medium, no new class of finding. High: `B413` (pycryptodome import, a
     false positive) and `B613` (`config/device_names.py` holds bidirectional characters on purpose in a regex
     that strips them). Medium: 15 `B608` (f-strings with constant table names and placeholder lists, checked
     by reading each), two `exec` in `updates.py` (the signed release loader, by design), `chmod 0o660` on the
     helper socket (by design), a bind to all interfaces in `config/adblocking.py:65` and `urlopen` in
     `measure.py:114`. None was exploitable from what was read.
6. Update path without a Pi (`tests/qa/test_release_scripts.py`)
   - `build-release.sh` and `check-release-manifest.sh` run on a Mac with git 2.54: version, build, manifest
     check, refusal of a changed commit, version or archive, refusal of eight malformed sequences. Every
     `deploy/raspberry-pi/*.sh` passes `sh -n`. Finding 5 is the only mismatch.
   - Pi-only parts (`install.sh`, systemd units, `preflight.py`, the update manager, `sign-release.sh` with a
     real key) were not run.
