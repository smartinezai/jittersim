Base: origin/integrate/main-into-stack (1044184), worktree claude-ux. PR 53 (phone layout) was NOT read: the session reached the usage stop line (weekly limit under 12% left) before that step. Shots are in `shots/`.

## How it was run and what is measured

The browser is the owner's Mac (192.168.50.20).
- Playwright shots of all 9 pages at 1440x900 and 390x844 (`21-..` to `29-..`, files `-full` and `-viewport`), sign-in (`00-..`), service lists (`41`), device area (`42`, `43`), after Panic (`44`).
- MEASURED: inventory counts, page heights, polling behaviour, Panic result, text of every page.
- INFERRED FROM THE PAGE STRUCTURE (not timed, not fully clicked through): click counts for tasks b, e, f, g, h, i below. Marked "est.".
- NOT DONE: dialogs beyond sign-in/credentials, spinners/slow-button timing, PR 53 review, real impact numbers (the first, aborted run pressed Panic, so Diagnostics/Traffic showed "Network is reset").

- "Open device controls" (6x) opens nothing visible as a new view in my run (no dialog, same page).

- Impact (does it work?) is on Diagnostics; rates on Traffic; before/after comparison on Measurements needs a CLI on the phone.

## 15 worst problems, ranked

1. Too many places to do the same thing (apply profile in 5 ways, stop in 4 ways); the page is organised by feature, not by task. Evidence: inventory above.
2. Per-device profile vs general profile conflict is unexplained: row shows "Saved device rules paused" next to an enabled "Apply profile" (`21-devices-1440-viewport.png`).
3. No path for "block one app for one device"; app blocking is split over Profiles (website access), Schedules and limits (service lists, browser service profile, service data limit, service time limit) and Access and rules.
4. Devices page is a 6-card wall of identical controls (55 controls, 3241 px desktop, 6177 px phone). Every row repeats 2 selects, 4 buttons, an "Edit name and type" fold and the group hint.
5. Profiles page mixes saved profiles, a 19-field form with 16 help icons, an "Assign a device" form that wants Device ID, IPv4 and Profile ID typed by hand, and Group devices (`22-profiles-1440-full.png`).
6. Sidebar is overloaded and clipped: nav, status box, Re-apply (?), Reset network (?), status text, toast copy, Panic, Router switch, 4 tiles. At 1440x900 the tiles at the bottom are cut off; it duplicates content of the pages.
7. Panic and Reset network side by side with different meanings and two "?" buttons; after Panic the next step is a long banner on every page.
8. Impact ("does it work") is not where the impairment is set; it is on Diagnostics, and Measurements needs a command line on the phone.
9. Router control is split: sidebar switch (disabled, reason terse), Router page setup, Wi-Fi name reset first, fallback collapsed, update tools at the bottom (`24-router-and-wi-fi-1440-full.png`).
10. Updates are on the Router page, can only install what an admin staged, and say nothing useful when none is staged (h).
11. Schedules and limits is 9 collapsed accordions with count pills and mixed concepts (schedule, timer, scenario, progression, 4 kinds of limits, 3 kinds of service rules); "Device data limit" was left open while others closed (`23-schedules-and-limits-1440-full.png`).
12. Protected/unaffected has five wordings, and a protected device keeps disabled controls on screen.
13. Jargon and internal IDs on screen: "(bad-3g)" appended to every profile name in selects, Profile ID, Device ID, reserved IPv4, "compiled plan", "configuration version", raw JSON on Diagnostics.
14. Same status said 3 times (toast, sidebar box, message line) and the toast covers the row buttons (`21-devices-1440-viewport.png`); successes and errors compete for attention.
15. Privacy rule: before sign-in the page title is "jittersim" and the heading and landmark say "JitterSim" (`00-signed-out-1440.png`); first-time users also need token, close panel, then "Allow this device" (3 steps with no progress hint, `00c-allow-device-1440.png`).

Honourable mentions: Access and rules mixes dashboard access, MAC filtering, website filtering and DNS failure chance with 5 textareas ("comma separated"); the 390 px layout is long (Devices 6177 px) although nothing overflows sideways.

## Responsiveness notes (measured)

- Polling every 5 s does NOT re-render the focused device row: node, focus and scroll position survived a 7 s wait (good).
- Not measured: spinners, button latency, flicker on Apply, because of the usage stop. Panic reacted within the 300 ms I waited.

## Overhaul directions (short)

1. Task-first navigation of 4 areas: Devices (one list, one sheet per device with Profile, Block an app, Impact, Protect), Profiles (library and builder), Network (router, Wi-Fi, access rules, updates), Activity and checks (traffic, impact, measurements, log, diagnostics).
2. Persistent top bar: status, Panic with one clear "Resume", router switch; remove the sidebar status block and duplicate toasts.
3. One way to apply: pick profile on the device sheet, or "Everyone" at the top of the list; explain the general-vs-device order in one sentence there.
4. A per-device "Impact" strip in each sheet (before/after, one check button).
5. Generate IDs from names; hide advanced fields; use plain words ("Protected" only).
6. Remove the pre-sign-in name; show a single sign-in step that also registers the device.
